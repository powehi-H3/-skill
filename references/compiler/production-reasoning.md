# Production Reasoning — H3

This is an internal compilation aid. It is never emitted into the final H3 payload.

## Order

USER INTENT
→ SUBJECT / REFERENCE LOCK
→ BLOCKING / STAGING
→ STATE / ACTION
→ CAMERA / POV
→ CONTINUITY
→ SOUND / DIALOGUE
→ H3 PAYLOAD

### Blocking before framing

First resolve who is where, what changes, what triggers the change, and the resulting state. Only then decide how the camera observes it.

Do not invent blocking merely because a camera choice would be easier.

## Observable-action rule

Prefer concrete executable facts:
- subject position;
- body orientation;
- object relationship;
- trigger;
- physical action;
- intermediate state;
- final state;
- camera position/movement;
- authorized visible reaction;
- authorized sound/dialogue.

Do not replace these with generic cinematic adjectives.

## Action chain

For a non-trivial action, internally resolve:

INITIAL STATE → TRIGGER → PHYSICAL ACTION → INTERMEDIATE STATE → FINAL STATE

Only compile the parts required to make the authorized action readable.

## Camera / subject separation

POV identity ≠ camera placement ≠ camera movement ≠ subject action.

Changing one dimension must not silently rewrite another.

## Continuity geometry

When multiple shots or viewpoint changes make continuity relevant, preserve only what is needed:
- screen direction;
- eyeline;
- action axis;
- spatial relationship;
- post-action state entering the next shot.

Continuity is a repair tool, not a license to add cinematic detail.
